# ados-releases

إصدارات جاهزة للتثبيت (`.whl`) من أدوات `Agentic Delivery OS` — لا كود مصدري هنا.

المصدر الحقيقي: مستودع `Agentic_Delivery_OS` الأساسي. هذا المستودع للتوزيع فقط، عبر
[Releases](../../releases). **مستودع عام** — لا كود حسّاس هنا (طبقة الإدارة مُستبعدة
تمامًا من كل حزمة هنا بتصميمها)، فلا حاجة لتوكن عند التثبيت.

## الحزم المتاحة

| الحزمة | لمن | الأوامر |
|---|---|---|
| `ados-exec` | فرق التنفيذ — تشغّل `epic-runner`/`ticket-executor`/`ticket-reviewer` على مستودعها فقط | `validate` · `readiness` · `sync` |

## التثبيت

```bash
pip install https://github.com/Ai-NativeLab/ados-releases/releases/download/ados-exec-v0.1.0/ados_exec-0.1.0-py3-none-any.whl
```

تحقّقتُ من هذا الأمر فعليًا في بيئة نظيفة معزولة قبل نشره هنا.

## الترقية

نفس الأمر بعد تحديث رقم الإصدار في الرابط لأحدث نسخة على [صفحة Releases](../../releases)، أو:

```bash
pip install --upgrade <رابط الإصدار الأحدث>
```

## الأوامر التي يستخدمها المطوّر المنفّذ

كل الأوامر أدناه تُشغَّل من **جذر المستودع** الذي تعمل عليه (`raseen-backend` أو
`raseen-frontend` مثلًا) — تقرأ `.claude/execution.json` (أو `.agents/execution.json`
حسب عميلك) الموجود فيه فعلًا؛ لا تحتاج كتابته بنفسك، القيادة توفّره جاهزًا.

قاعدة أكواد الخروج في كل أمر: `0` نجاح، `1` فشل حقيقي — مفيد لو استدعيتها من سكربت.

### 1) `ados validate` — تحقّق أن العقد سليم

```bash
ados validate .claude/execution.json
```

يقرأ ملف العقد ويقارنه بالمخطط الرسمي (JSON Schema). يُستخدم أولًا في أي جلسة —
عقد لا يجتاز هذا التحقق يعني توقّف أي مهارة فورًا قبل أن تبدأ، فتشغيله يدويًا مفيد
لتشخيص خطأ عقد بمعزل عن باقي العمل. المخرج: `[OK]` أو `[FAIL]` مع تفصيل الحقل الناقص/الخاطئ.

**متى تحتاجه فعليًا:** نادرًا يدويًا — المهارات (`epic-runner`/`ticket-executor`) تشغّله
تلقائيًا في أول خطوة لها. شغّله بنفسك فقط عند تشخيص عطل أو بعد تعديل العقد.

### 2) `ados readiness` — تحقّق أن المستودع المحلي جاهز لبدء ملحمة

```bash
ados readiness --contract .claude/execution.json
```

يتحقق: هل أنت على الفرع الأساسي (`component.main_branch`)؟ هل شجرة العمل نظيفة (لا
تغييرات معلَّقة)؟ هل الفرع محاذٍ للبعيد؟ — ويسحب آخر التعديلات تلقائيًا (`git pull`
آمن، fast-forward فقط) حين يكون ذلك ممكنًا بلا مخاطرة.

خيارات إضافية:
- `--remote <اسم>` — اسم البعيد إن لم يكن `origin` (نادر).
- `--no-pull` — افحص فقط بلا سحب تلقائي حتى لو كان آمنًا.

**متى تحتاجه فعليًا:** `epic-runner` يشغّله تلقائيًا قبل أي فرع أو تذكرة. شغّله يدويًا
لو أردت التأكد من جاهزيتك **قبل** أن تطلب من عميلك بدء ملحمة — يوفّر توقفًا لاحقًا لو
كانت شجرة عملك متسخة من عمل سابق لم تُكمله.

### 3) `ados sync` — زامن حالة تذكرة (أو ملحمة كاملة) مع GitHub

```bash
ados sync --contract .claude/execution.json --ticket RSN-101
# أو لكل تذاكر ملحمة دفعة واحدة:
ados sync --contract .claude/execution.json --epic EPIC-003
```

يكتب حالة التذكرة الحالية (من ملفها المحلي أو حقولها) إلى بطاقة GitHub المقابلة —
ينشئها إن لم توجد، يحدّثها إن وُجدت. خيارات مفيدة:
- `--comment "نص"` — يعلّق تعليقًا إضافيًا على البطاقة مع المزامنة (مثلاً توضيح قرار).
- `--strict` — يفشل (كود خروج `1`) عند غياب توكن GitHub، بدل تحذير مع استمرار العمل.

**متى تحتاجه فعليًا:** نادرًا يدويًا — `ticket-executor`/`ticket-reviewer` يزامنان تلقائيًا
عند كل تغيّر حالة حقيقي (بدء تنفيذ، تسليم للمراجعة، اعتماد/رفض). شغّله يدويًا فقط لو
شككت أن مزامنة تلقائية فشلت صامتة وتريد إعادتها، أو لإضافة تعليق يدوي على بطاقة.

**يتطلب `GITHUB_TOKEN`** في متغير بيئة (اسمه الفعلي في `sync.github_token_env` بالعقد،
افتراضيًا `GITHUB_TOKEN`) — يضبطه كل مطوّر في بيئته هو، لا يُكتب في أي ملف أبدًا.

### 4) تنفيذ الملاحم والتذاكر نفسه — ليس أمر `ados`

التنفيذ الفعلي (كتابة الكود، تشغيل الاختبارات، فتح التذاكر) لا يُطلَب بأمر طرفية —
تطلبه من عميلك الذكي (Claude Code أو ما يعادله) مباشرة بجملة عادية، وهو من يستدعي
أوامر `ados` أعلاه تلقائيًا في الخلفية حسب الحاجة:

```
نفّذ EPIC-003 عبر epic-runner
```

أو لتذكرة واحدة فقط:

```
نفّذ RSN-101
```

epic-runner يخطّط، يتوقف عند كل قرار مهم لتأكيدك (البدء، الانتقال بين التذاكر، الدفع،
فتح طلب الدمج)، ويستدعي `ticket-executor` ثم `ticket-reviewer` بالترتيب. لا تكتب كود
أو تشغّل اختبارًا بنفسك خارج هذا التدفق — هذا دور المهارات، لا المطوّر مباشرة.
