# ados-releases

إصدارات جاهزة للتثبيت (`.whl`) من أدوات `Agentic Delivery OS` — لا كود مصدري هنا.

هذا المستودع للتوزيع فقط، عبر [Releases](../../releases). **مستودع عام** — لا كود حسّاس
هنا (طبقة الإدارة مُستبعدة تمامًا من كل حزمة هنا بتصميمها)، فلا حاجة لتوكن عند التثبيت.

## الحزم المتاحة

| الحزمة | لمن | الأوامر |
|---|---|---|
| `ados-exec` | فرق التنفيذ — تشغّل `epic-runner`/`ticket-executor`/`ticket-reviewer` على مستودعها فقط | `install` · `validate` · `readiness` · `sync` |

## التثبيت

```bash
pip install https://github.com/Ai-NativeLab/ados-releases/releases/download/ados-exec-v0.2.3/ados_exec-0.2.3-py3-none-any.whl
```

تحقّقتُ من هذا الأمر فعليًا في بيئة نظيفة معزولة قبل نشره هنا.

## الترقية

نفس الأمر بعد تحديث رقم الإصدار في الرابط لأحدث نسخة على [صفحة Releases](../../releases)، أو:

```bash
pip install --upgrade <رابط الإصدار الأحدث>
```

## الأوامر التي يستخدمها المطوّر المنفّذ

**عام لأي مشروع وأي عميل وكيل** — لا شيء هنا خاص بمستودع بعينه أو بأداة بعينها. الفرق
الوحيد بين مشروع وآخر هو محتوى عقد التنفيذ نفسه (`.ados/execution.json`)، لا الأوامر.

كل أمر أدناه يُشغَّل من **جذر مستودعك**. `.ados/` مجلد محايد لا يخص أي وكيل بعينه —
يحمل عقد التنفيذ (بيانات مشروعك: مصدر تذاكره، فرعه الأساسي، أوامر الفحص...) وحده،
لا نص أي مهارة. قاعدة أكواد الخروج في كل أمر: `0` نجاح، `1` فشل حقيقي.

### 1) `ados install` — ثبّت نصّ المهارات لوكيلك

```bash
ados install
```

يسألك تفاعليًا: أي وكلاء عندك؟ (حاليًا: Claude → `.claude/skills/`، Agy → `.agents/skills/`)،
وينسخ نصّ `epic-runner`/`ticket-executor`/`ticket-reviewer` إلى مجلد كل وكيل تختاره.
غير تفاعلي: `ados install --agents claude,agy`. لتثبيت في مسار آخر غير المجلد الحالي:
`--target <مسار>`. هذه الحزمة تُثبِّت طبقة `execution` فقط (الافتراضي) — طلب `--layer management` يفشل برسالة توجّهك للحزمة الكاملة.

**لا يلمس `.ados/execution.json` إطلاقًا** — عقد مشروعك بيانات حقيقية خاصة به، لا يولّدها
أمر تركيب عام. يجب أن يكون موجودًا في المستودع فعلًا قبل أي استخدام للمهارات.

**متى تحتاجه فعليًا:** مرة واحدة بعد `git clone` (أو بعد كل ترقية للحزمة، لأن نص المهارات
قد يتحدّث بين إصدار وآخر).

### 2) `ados validate` — تحقّق أن العقد سليم

```bash
ados validate .ados/execution.json
```

يقرأ ملف العقد ويقارنه بالمخطط الرسمي (JSON Schema). عقد لا يجتاز هذا التحقق يعني توقّف
أي مهارة فورًا قبل أن تبدأ، فتشغيله يدويًا مفيد لتشخيص خطأ عقد بمعزل عن باقي العمل.
المخرج: `[OK]` أو `[FAIL]` مع تفصيل الحقل الناقص/الخاطئ بدقة.

**متى تحتاجه فعليًا:** نادرًا يدويًا — المهارات تشغّله تلقائيًا في أول خطوة لها. شغّله
بنفسك فقط عند تشخيص عطل أو بعد تعديل العقد.

### 3) `ados readiness` — تحقّق أن المستودع المحلي جاهز لبدء ملحمة

```bash
ados readiness --contract .ados/execution.json
```

يتحقق: هل أنت على الفرع الأساسي المُعرَّف في العقد؟ هل شجرة العمل نظيفة (لا تغييرات
معلَّقة)؟ هل الفرع محاذٍ للبعيد؟ — ويسحب آخر التعديلات تلقائيًا (`git pull` آمن،
fast-forward فقط) حين يكون ذلك ممكنًا بلا مخاطرة.

خيارات إضافية:
- `--remote <اسم>` — اسم البعيد إن لم يكن `origin` (نادر).
- `--no-pull` — افحص فقط بلا سحب تلقائي حتى لو كان آمنًا.

**متى تحتاجه فعليًا:** المهارة المنسِّقة لتنفيذ ملحمة كاملة تشغّله تلقائيًا قبل أي فرع أو
تذكرة. شغّله يدويًا لو أردت التأكد من جاهزيتك **قبل** أن تطلب من عميلك بدء ملحمة — يوفّر
توقفًا لاحقًا لو كانت شجرة عملك متسخة من عمل سابق لم تُكمله.

### 4) `ados sync` — زامن حالة تذكرة (أو ملحمة كاملة) مع نظام التتبّع

```bash
ados sync --contract .ados/execution.json --ticket <معرّف التذكرة>
# أو لكل تذاكر ملحمة دفعة واحدة:
ados sync --contract .ados/execution.json --epic <معرّف الملحمة>
```

يكتب حالة التذكرة الحالية إلى بطاقتها في نظام التتبّع (GitHub Issues عادةً) — ينشئها
إن لم توجد، يحدّثها إن وُجدت. خيارات مفيدة:
- `--comment "نص"` — يعلّق تعليقًا إضافيًا على البطاقة مع المزامنة (مثلاً توضيح قرار).
- `--strict` — يفشل (كود خروج `1`) عند غياب توكن الوصول، بدل تحذير مع استمرار العمل.

**متى تحتاجه فعليًا:** نادرًا يدويًا — مهارات التنفيذ تزامن تلقائيًا عند كل تغيّر حالة
حقيقي (بدء تنفيذ، تسليم للمراجعة، اعتماد/رفض). شغّله يدويًا فقط لو شككت أن مزامنة تلقائية
فشلت صامتة وتريد إعادتها، أو لإضافة تعليق يدوي على بطاقة.

**يتطلب توكنًا** في متغير بيئة (اسمه الفعلي في `sync.github_token_env` بالعقد، افتراضيًا
`GITHUB_TOKEN`) — يضبطه كل مطوّر في بيئته هو، لا يُكتب في أي ملف أبدًا.

### 5) تنفيذ الملاحم والتذاكر نفسه — ليس أمر `ados`

التنفيذ الفعلي (كتابة الكود، تشغيل الاختبارات، فتح التذاكر) لا يُطلَب بأمر طرفية —
تطلبه من عميل الوكيل لديك مباشرة بجملة عادية، وهو من يستدعي أوامر `ados` أعلاه تلقائيًا
في الخلفية حسب الحاجة:

```
نفّذ <معرّف الملحمة> عبر المهارة المنسِّقة لتنفيذ الملاحم
```

أو لتذكرة واحدة فقط:

```
نفّذ <معرّف التذكرة>
```

المهارة المنسِّقة تخطّط، تتوقف عند كل قرار مهم لتأكيدك (البدء، الانتقال بين التذاكر،
الدفع، فتح طلب الدمج)، وتستدعي مهارتي التنفيذ والمراجعة بالترتيب. لا تكتب كود أو تشغّل
اختبارًا بنفسك خارج هذا التدفق — هذا دور المهارات، لا المطوّر مباشرة.
